# CW 编解码（键控输入 · 摩斯解码 · 音频合成）

> 本文件只负责 CW 信号与字母之间的「编解码」，分三层：
> - 发送侧：键盘 / 键控 → 点划时序（keyer）
> - 接收侧：点划 / 时序 → 字母（摩斯解码）
> - 输出侧：文本 → CW 音频（编码）
>
> 报文的「语义解析」（字母文本 → `ParsedMessage`，含呼号 / RST / 结束语提取）是**独立模块**，见 [报文解析](./MESSAGE-PARSING.md)。本文件只产出 / 消费字母，不做语义判断。
> 相关：报文格式规范见 [QSO 协议](./QSO-PROTOCOL.md)；音频环境（底噪 / QSB / QRM）见 [音频与电磁环境](./AUDIO-ENVIRONMENT.md)；界面见 [界面](./UI.md)。

## 键盘输入与 CW 发送（发送侧 keyer）

> **已实现（2026-10-14）**：核心在 `src/cw/keyer.ts` 的 `IambicKeyer` —— Mode A/B、点划记忆（squeeze）、快速连按排队、自动 3d 字符间隔与**按沉默时长分词**均已落地。它的时钟与驱动全部由外部注入（每个方法都接收 `now`），因此行为完全确定、可单测。UI 接线见 `src/ui/keyer.ts` 的 `IambicKeyerInput`，界面面板见 `src/ui/pages/keyPanel.ts`，设置页可切换「报文 / 直键 / 双键」并绑定点划键位。
>
> **侧音**也已实现（`src/audio/sidetone.ts`，详见 [音频与电磁环境](./AUDIO-ENVIRONMENT.md) 的「发报侧音」）：它不走报文音频，而是常驻振荡器实时开关，按下即响、松开即停。

### 键位绑定

- 用户可自定义
- 直键：一个键
- iambic：点键 + 划键
- 默认：空格为直键；`KeyZ` 为点键、`KeyX` 为划键（相邻，便于双桨同按 squeeze；也不与浏览器快捷键冲突）。二者均可在设置页改绑
- 侧音：发报同时播出监听音。直键跟随按键按下/松开；iambic 只跟随元素起止，自动插入的间隔保持静音。侧音是本地监听音，**不受 QSB/QRM/QRN 影响**（见 [音频环境](./AUDIO-ENVIRONMENT.md)）

### 直键（Straight Key）

- 按下发 CW，松开停止
- 用户手动控制点划时长

### iambic 键

支持两种模式：

| 模式 | 行为 |
|---|---|
| Mode A | 松开双桨时，只完成当前元素，不发送记忆的下一个元素 |
| Mode B | 完成当前元素后，还会发送记忆的下一个元素 |

两种模式均可切换。

### 辅助功能

| 功能 | 说明 |
|---|---|
| 点划记忆 | 按点后按划，会发送点划 |
| 快速连按 | 元素还没发完时按下的键会排队，按顺序随后发出——手快不会丢键 |
| 自动字符间隔 | 系统自动插入 3 单位间隔 |
| 自动分词 | 与上一个元素相隔 **≥7 个点长**再按下，就算新词——分词靠停顿，不按任何键 |

### 发送显示

- 解码出的字符直接写进发送框，由操作者核对后再发
- 不统计错误率

## 摩斯解码（接收侧：点划 / 时序 → 字母）

> 本层是 CW-PARSING 的核心：把用户通过直键 / iambic 产生的点划时序（按下 / 松开事件流）还原为字母文本，交给 [报文解析](./MESSAGE-PARSING.md) 做语义解析。它**只认符号，不认含义**——不在此层判断呼号 / RST / 结束语。

### 时序基准

以「点」为单位时长 `d`（由 WPM 决定：`d = 1200 / WPM` 毫秒）：

| 元素 | 时长 |
|---|---|
| 点（·） | `d` |
| 划（−） | `3d` |
| 元素间隔（同字符内） | `d` |
| 字符间隔 | `3d` |
| 单词间隔 | `7d` |

- **Farnsworth 间隔**：CW 训练常用的节奏技巧，把速度拆成两层——字符本身（点 / 划及其元素间隔）仍按较快速度发，而字符间 / 单词间的停顿被拉长（等效于较慢速度），即「字符快、间隔慢」，便于初学者边听边抄。本解码器支持它：放大字符 / 单词间隔而不改变点划与元素间隔的基准速度；也因此**不能假设字符间隔恒为 3d**，否则会把 Farnsworth 节奏误判为字符粘连。
- 解码出的字符直接写进发送框，供操作者核对后再发。

### 符号判定（按键时长 → 点 / 划）

- 一次按键（ON）时长 `< 2d` → 点（·）
- 一次按键时长 `≥ 2d` → 划（−）
- 模糊区（约 `2d` 附近）：`d` 直接取所有按键中最短的点时长（见 `src/cw/decoder.ts` 的 `estimateUnit`），点划按 `< 2d` / `≥ 2d` 硬阈值判定；轻微手感抖动与整体速度漂移被基准估计自动吸收，无需单独 ±0.5d 容差带。

### 间隔判定（静默时长 → 字符 / 单词边界）

- 静默（OFF）`< 2d` → 仍属当前字符的元素间隔
- 静默 `≥ 2d` → 字符结束（字符间隔）
- 静默 `≥ 单词阈值` → 单词结束（单词间隔，输出一个空格）

**单词阈值不是固定的 `5d`**，而是 `max(5d, 1.8 × 最小字符间隔)`（见 `src/cw/decoder.ts` 的 `decodeKeying`）：

- 标准节奏下最小字符间隔就是 `3d`，`1.8 × 3d = 5.4d`，所以实际阈值是 **5.4d**，落在字符间隔 `3d` 与发送侧标准词间隔 `7d` 之间。
- Farnsworth 会把字符间隔拉长而保住点划速度，阈值随之抬高，才不会把被拉长的字符间隔误判成词边界。
- 一段按键里没有可测的字符间隔时，按 `3d` 代入，阈值同样是 `5.4d`。

比例表里的 `7d` 是**发送侧**给出的标准词间隔（见 `src/cw/encode.ts`）；**接收侧**只要求明显大于字符间隔即可判定词边界，不必等到满 `7d`。

| G | −−· | T | − |

| J | ·−−− | W | ·−− |
| K | −·− | X | −··− |

| 数字 | 码 | 数字 | 码 |

> 解码时先按元素序列查表；查不到的字符标记为未知（不臆造），交由上层处理。

### 容错

- 元素 / 间隔时长落在阈值模糊区时，按最近档判定。
- 字符间隔缺失（连发无间隔）仍按元素序列查表，查不到则标记未知字符。
- 点划基准 `d` 取所有按键中最短的点时长（见 `src/cw/decoder.ts` 的 `estimateUnit`），轻微手感抖动与整体速度漂移被自动吸收，避免轻微偏差导致整字符错译。
- 未知字符不阻断后续解码，整体输出仍交给 [报文解析](./MESSAGE-PARSING.md)。

### 输出

- 本层输出：一串大写字母文本（空格分隔单词），例如 `CQ CQ CQ DE BG7XXX`。
- 不在此层做呼号 / RST / 结束符的语义判断——那是 [报文解析](./MESSAGE-PARSING.md) 的职责。

## 报文转音频（编码 / CW keyer 输出）

> 把一条文本报文按 WPM 与 Farnsworth 规则编码为 CW 音频（点 / 划时序 + 700 Hz 音调）。输入是文本（含 HAM 标准报文），输出是音频。

### 速度与时序

- WPM 范围：**5 – 40**，默认 **18**
- 支持 Farnsworth 间隔（含义见上方「摩斯解码」层：字符快、间隔慢，练习初期 / 低难度时使用）
- 标准比例：点 : 划 : 字符间隔 : 单词间隔 = **1 : 3 : 3 : 7**

### CW 音调生成

- 默认：**700 Hz**
- 可调范围：**300 – 1200 Hz**
- 波形：正弦波
- 实现：点划时长直接排成**发射机的增益斜坡**（`src/audio/bandSynth.ts`：常驻振荡器 × 键控增益，起落各 5 ms 斜坡），实时敲到频率上；QSB 是乘在同一台增益上的慢速包络，QRN / QRM 混进总线（见 [音频与电磁环境](./AUDIO-ENVIRONMENT.md) 的「音频处理架构」）。侧音同理，只是走自己的振荡器。
