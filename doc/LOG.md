# 日志与存储

> 本文件描述**练习日志**（写入条件、字段、核对、允许的操作）与**数据存储**（设置、日志、静态资源的落地方式）。
> 相关：界面上的日志页见 [界面](./UI.md) 的「视图结构」；比赛模式的分区 / 序号与核对规则见 [比赛模式](./CONTEST.md)；免责声明（日志不可用于奖项）见项目根目录的 [README](../README.md)。

## 写入条件

日志由**操作者亲手写**，不由状态机代写。电台页的录入行里填上对方呼号与两个 RST（比赛模式还要填对方的分区 / 序号，见 [快速报文与日志录入](./MESSAGES.md) 的「录入行」），在最后一步按回车（发出结束语 F3）的那一刻，这一行就记进日志——**不等这句发完，也不等对方回 73**：结束通联是操作者的动作，纸上的字不会等对方确认。

写入只看一件事：**该填的框都齐了**——呼号非空、两个 RST 都是三位有效数字（`599`、`579` 这样）；比赛模式再加上"第四格是合法的分区或序号"。程序不检查状态机走到了哪一步，也不验证这次通联是否真的成立：真实日志本记的是操作者抄下来的东西，抄错呼号、没等对方签收就收工，都由操作者自己负责。

> 实现：门槛集中在 `canLog()`（`src/ui/entryModel.ts`），落账在 `buildLogRecord()`（`src/ui/logRecord.ts`）——两者都是纯函数，表本身只负责渲染。同一次通联不会被写两遍：写完之后框立即清空，下一行是新的一条。

## 日志字段

| 字段 | 含义 | 来源 | 格式 |
|---|---|---|---|
| `DATE` | 通联日期（UTC） | 写日志那一刻 | `YYYY-MM-DD` |
| `TIME_UTC` | 通联时间（UTC） | 写日志那一刻（按下回车发 F3 时） | `HH:MM:SS` |
| `CALL` | 对方呼号 | 录入行（自动转大写） | 大写 |
| `FREQ_MHZ` | 通联频点（拨轮频率） | 写日志那一刻的拨轮 | `14.0250` |
| `MODE` | 模式 | 固定 `CW` | 固定 `CW` |
| `RST_RX` | 对方发给我的 RST | 录入行 | 三位数字 |
| `RST_TX` | 我发给对方的 RST | 录入行（默认 `599`） | 三位数字 |
| `EXCH_RX` | 对方发来的分区 / 序号 | 录入行第四格（**仅比赛模式**） | `05` / `001` |
| `EXCH_TX` | 我发出去的分区 / 序号 | 落账那一刻设置里的值（**仅比赛模式**） | `05` / `001` |

> 时间与频率都取"落账那一刻"：结束语刚刚开播，拨轮还没有转走——纸上也是这么记的。

> `MODE` 恒为 `CW`：`CW-L` / `CW-U` 是接收机在哪一侧解调的操作偏好，不是工作模式，不进日志——真实日志本也是这样。

> 比赛模式的两列**记的是录入行与设置里的数字**，不是空中的短码：`T5`、`TTA` 是发报的写法，日志里仍是 `05`、`001`。

## 核对

每一行带一个**核对结果**：这一条抄得对不对。它只在比赛模式之外的场合也一样有——日常通联同样会判呼号与 RST。

| 显示 | 含义 |
|---|---|
| `正确` | 抄对了 |
| `呼号错误` | 对方呼号抄错了——这条其实是另一次通联的记录 |
| `交换信息错误` | 呼号对，分区 / 序号抄错了（仅比赛模式） |
| `RST 错误` | 前两项都对，只有报告抄错了 |
| `—` | 没有与该台的收发过程可比（手记的条目） |

- **在落账那一刻判定**：用的是"对方真正发的是什么"（`session.partnerTruth()`），而对方一旦被放回波段就无从对照，所以必须是那一刻。
- **只说错在哪一项，不给出正确答案**。屏幕上不显示对方是谁，这条原则不因通联结束而失效：把正确分区印在日志里，抄收就从"听"变成了"读"。
- **改过的行丢掉核对结果**：判断是对"当时抄下来的那一份"下的，行被编辑，被判断的那份就不在了。

判定顺序、`5` / `05` / `005` 算同一个数这类细节见 [比赛模式](./CONTEST.md) 的「核对：错在哪一项」。

## 三本日志

三种通联模式（`DX` / `CQWW` / `WPX`）**各自一本**，互不混淆：日常通联与比赛通联不是同一种记录，CQWW 的分区与 WPX 的序号也不是同一种数字。

- 日志页顶部是三个标签，每个标签写着该本的条数；点哪个看哪个。
- **编辑、删除、清空都只作用于当前标签**——除此之外只有一个"清空全部日志"会跨三本。
- 日志页跟着当前通联模式打开；也可以随手翻别的本子看。

## 日志操作

- 支持**手动编辑**单条记录（保存后该行的核对结果随之消失）
- 支持**删除**单条记录
- 支持**清空当前这本**，以及**清空全部**（跨三本）；两者都要**点两次**——第一次只把按钮换成「再点一次…」，第二次才真删。日志删了就找不回来，所以不许一次点完
- **不支持导出**为 ADIF、CSV、JSON 等任何格式（去争议化：练习日志不能变成可申报的凭证）

日志页常驻一条水印：

```text
练习日志，非真实通联记录，不可用于任何奖项申请。
```

## 数据存储

### 存储方案

- 日志：IndexedDB（`src/ui/storage/logStore.ts`）
- 设置：localStorage，单键 JSON（`src/ui/storage/settingsStore.ts`）
- 未完成的一次通联：localStorage 暂存（`src/ui/storage/qsoStaging.ts`）
- 两端**跑的是同一套 Web 存储**，没有原生侧数据库：Tauri 版不写 Rust 存储代码，只用 `src-tauri/tauri.conf.json` 的 `appDirectoriesOverride: "./app-data"` 把 WebView2 的数据目录（含 IndexedDB 与 localStorage）落到 exe 旁的 `app-data/`，所以把 exe 与该目录一起拷走即可带走全部设置与日志。

### 数据类型

| 数据 | 存储 | 说明 |
|---|---|---|
| 用户设置 | localStorage | 单键 JSON、整份覆盖 |
| 日志 | IndexedDB | 自增主键，可改可清，**无导出** |
| 未完成的一次通联 | localStorage（暂存） | 逐行写入，刷新可续；完成或失败即清除 |
| 前缀表 `data/cty.dat` | 静态资源 | 随应用打包，只读 |

### 降级

所有存储访问都做了保护：没有 IndexedDB（如 jsdom、隐私模式）时日志页提示"无法保存"而不是抛错；localStorage 不可用时暂存与设置退回内存默认值。**界面本身不因存储不可用而失败**。

### 离线运行

- 所有资源本地打包
- 不依赖网络
- Web 原型即可离线运行；最终由 Tauri 打包为桌面 exe（PWA 不做，见 [开发路线](./ROADMAP.md) 的平台一节）
