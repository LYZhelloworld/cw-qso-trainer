# 快速报文与日志录入

> 本文件描述**模式配置文件**（八个功能键的报文从哪来、怎么写、有哪些宏）与**日志录入行**（三个输入框、高亮与回车/空格、Run 与 S&P）。
> 相关：日志字段与存储见 [日志与存储](./LOG.md)；通联状态机见 [通联过程](./QSO-PROTOCOL.md)；界面布局见 [界面](./UI.md) 的「操作行」。

---

## 八个功能键

电台页上有一组八个功能键（F1–F8），四种发报方式（报文 / 直键 / 双桨）共用同一组，位置固定：波段细带之下、瀑布图之上，与日志录入行构成屏幕上唯一"要用手输入"的一块。

- **四列两行**：按钮等宽、等高、间距一致，不随窗口宽度变形。
- **快捷键就是 F1–F8**：在任何位置按下都等同于点击（设置弹窗打开时除外）。浏览器自己也用这些键（F1 帮助、F3 查找、F5 刷新），按下时一律被界面吃掉。
- **灯跟着该说的下一句走**：当前该发的那个键高亮（见下方「录入行」）。灯表示**步骤**，不表示可用性——S&P 的第一步是"呼叫对方"，而那句话需要对方呼号，此刻还没抄到，灯亮着但按不动（见下方「缺值不发」）。
- **灰掉的键按不动**，两种情况：这一行报文留空（保留键），或用到的宏此刻还没有值。

发出的报文一律先展开宏（见下方「宏」），再交给会话——**和手动输入一条报文没有区别**：会不会有人应答、谁应答，仍由报文内容和当下谁在听决定（见 [通联过程](./QSO-PROTOCOL.md) 的「发报即开始」）。因此按 F1 发 CQ 就是发起一次呼叫，按 F2 交换 RST 就推进当前这次通联。

发报期间（半双工）按键与回车都不生效：机器还在发，没有什么可以"再说一句"。

## 模式配置文件

八个键的报文不在程序里，而在**当前模式的一个文本文件**里。现在只有 DX 模式（只交换呼号与 RST 的普通通联），文件名 `DX.msg`。

- **内置默认**：默认报文随程序打包，与 [日志与存储](./LOG.md) 里的其他静态资源一样离线、只读。
- **用户可改**：桌面版首次运行时把内置默认写到 exe 旁的 `app-data/messages/DX.msg`，之后优先读这个文件；改完保存、重启程序生效。程序不会写回或覆盖已有的文件。
- **改坏了也不至于开不了台**：文件里一行都读不出可用报文时，退回内置默认，并在控制台说明原因（`[模式配置] DX：…`）；有毛病的行按行号报出来，其余照用。
- **浏览器版只读内置默认**：网页读不到自己旁边的文件，所以预览版永远用打包进去的那一份。

### 文件格式

一行定义一个键，`#` 开头的整行是注释：

```text
# 发送 CQ
F1 CQ,CQ CQ CQ DE {MYCALL} {MYCALL} PSE K
```

- `F<序号>` 只能是 1–8；同一序号写两遍，后写的覆盖先写的。
- 序号之后是 `按钮文字,报文`：**只有第一个逗号是分隔符**，报文里可以再写逗号。
- 按钮文字留空，按钮上就只显示 `F1` 这样的键名。
- 报文留空（或整行只写 `F8`），这个键作废。
- **没有行内注释**：报文里的 `#` 会照原样发出去，所以不能像 shell 那样在行尾追加说明。
- **文件里没写的键一律按作废处理**，不会退回内置默认——想要默认，就把它抄进去。

### 宏

报文里的 `{XXX}` 在**按下按键的那一刻**替换成当前值：

| 宏 | 用途 | 替换成 |
|---|---|---|
| `{MYCALL}` | 我的呼号 | `BG7XXX` |
| `{THEIRCALL}` | 对方呼号（录入行里填的那个） | `JA1ABC` |
| `{RST}` | 我发给对方的 RST，9 写成 N | `5NN` |
| `{RSTFULL}` | 我发给对方的 RST，全码 | `599` |
| `{EXCH}` | 比赛交换信息；DX 模式下为空 | （空） |

- **简码只换 9**：`599` → `5NN`、`579` → `57N`、`449` → `44N`。其他数字在 CW 里本来就短。
- **`{EXCH}` 允许为空**，DX 模式下它永远是空，不算缺值；其他宏没有值就算缺值。
- **缺值不发**：报文里只要有一个宏还没有值，这个键就是灰的。程序不会替操作者发一条缺了呼号、或者 RST 只发了一半的报文。按了高亮键但缺值时，录入行会指出缺的是哪个框并把光标送过去。
- 按钮文字里的宏同样展开（`F4 {MYCALL}` 显示成 `F4 BG7XXX`），值缺失时保留宏名原文，以便看出缺的是哪一项。

### 默认报文

| 键 | 按钮文字 | 报文 | 用途 |
|---|---|---|---|
| F1 | `CQ` | `CQ CQ CQ DE {MYCALL} {MYCALL} PSE K` | 发送 CQ |
| F2 | `RST` | `{THEIRCALL} DE {MYCALL} R UR RST {RST} {RST} K` | 交换 RST |
| F3 | `TU` | `R TU 73 SK` | 结束通联 |
| F4 | `{MYCALL}` | `{THEIRCALL} DE {MYCALL}` | 我的呼号，呼叫对方 |
| F5 | `{THEIRCALL}` | `{THEIRCALL}` | 对方呼号，点名 |
| F6 | `RST REPEAT` | `R UR RST {RST} {RST} K` | 重发一遍 RST |
| F7 | `?` | `?` | 要求对方重复 |
| F8 | — | — | 保留键，留空 |

F3 不依赖任何宏，所以它永远可按；F1/F2/F4/F5/F6 依赖呼号或 RST，缺值即灰（这也是"没填本方呼号时只有三个键可用"的原因）。

### 将来的模式

比赛模式（WPX、CQWW 等）用**同一套格式**，各自一个文件：`WPX.msg`、`CQWW.msg`。区别只在报文内容与 `{EXCH}` 的取值——那时交换信息不再是空的，而是序号或分区。程序侧只需要换一份 `ModeMessages`，八个键的渲染、宏展开、录入行都不用动。

## 录入行（日志记录）

八个键下面是三个输入框，**开始时全空**：

| 框 | 对应 | 一般填什么 |
|---|---|---|
| 对方呼号 | `{THEIRCALL}` | 抄下来的呼号（自动转大写、去空格） |
| 我发 RST | `{RST}` / `{RSTFULL}` | `599`（默认值，可改；只收数字、最多三位） |
| 对方 RST | — | 对方给过来的报告 |

这三个框就是**日志本身**：日志由操作者亲手写，不再由状态机代写（见 [日志与存储](./LOG.md) 的「写入条件」）。抄错呼号就记下抄错的呼号——真实日志本也是这样。

### 高亮与回车

界面按"现在该说哪一句"决定高亮哪个键。**回车 = 走这一步并把它发出去**；**空格 = 走同一步但不发**（想用电键自己敲、或者先不急着发的时候用）。

| 当前状态 | 高亮 | 回车 | 空格 |
|---|---|---|---|
| 呼号框为空 | F1（Run）/ F4（S&P） | 发 CQ / 呼叫对方 | 无动作 |
| 呼号已填 | F2 | 我发 RST 自动填 `599`，光标跳到"对方 RST"，同时发出 F2 | 同样填 `599`、跳光标，但**不发** |
| 对方 RST 已填 | F3 | 发出 F3，随后写入日志；清空三个框、光标回呼号框、灯回 F1 | 无动作 |

- 我发 RST 已经有值（比如自己改成 `579`）时，不会被 `599` 覆盖。
- 三个框都齐了才肯收尾：缺哪一项就指出哪个框，光标送过去，不发也不写。
- 写日志的时刻在**结束语发完之后**（先发出去，再落账），频率取那一刻的拨轮频率。
- 发报期间回车不生效：半双工，机器还在发。

### Run 与 S&P

上下两个单选框决定**空呼号框时先说什么**：

- **Run**（默认）：自己发 CQ，等别人来应答。空行按回车发 F1。
- **S&P**（Search & Pounce）：听到别人在 CQ，过去应答他。空行按回车发 F4。

除此之外两者完全一样：呼号一填，灯就转向 F2。之所以要手动选：空呼号框按回车时，程序没有任何线索能判断你是要 CQ 还是应答别人——这是操作者的意图，只能由操作者声明。切换只影响灯与回车，不改变已经填好的内容。

> S&P 的第一步是"呼叫对方"，而 `{THEIRCALL}` 那时还空着，所以 F4 亮着但按不动：先填呼号，它自己就通了。
