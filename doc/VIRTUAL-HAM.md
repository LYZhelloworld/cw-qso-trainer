# 虚拟 HAM 策略（生成、前缀与地理位置）

> 本文件集中描述虚拟 HAM 的**生成策略**、**呼号前缀与地理位置的关系**，以及虚拟 HAM 在频段上的**运行时行为**（含两类台、堆叠应答、后台互相通联）。
> 相关：QSO 状态机在各阶段调用这些行为，见 [QSO 协议](./QSO-PROTOCOL.md)；报文解析与呼号校验见 [报文解析](./MESSAGE-PARSING.md)；接收不全的音频触发见 [音频与电磁环境](./AUDIO-ENVIRONMENT.md)。

## 呼号前缀表与地理位置

### 数据来源

呼号前缀表落地为 [`../data/cty.dat`](../data/cty.dat)——业余无线电通用的**国家文件**，由 Jim Reisert AD1C 维护、[country-files.com](https://www.country-files.com/cty/) 发布，每周更新。文件随仓库入库，构建时以原始文本内联，构建过程不联网。

刷新它是一次显式动作：

```powershell
npm run update:cty
```

脚本先下到临时文件，校验结构（八段冒号字段、坐标可解析）与记录数（≥300 条）通过后才原子替换 `data/cty.dat`；任何一步不通过都保留原文件并返回非零。刷新结果作为一次可审阅的提交进入仓库。也可以手动从 [bigcty 页](https://www.country-files.com/bigcty/) 下载覆盖，解析规则不变。

### 从文件到内存

解析器在 [`../src/data/cty.ts`](../src/data/cty.ts)。一条记录一个 DXCC 实体：首行是八段冒号分隔字段，随后若干行别名。

| 文件中的字段 | 落到 `DxccEntity` | 说明 |
|---|---|---|
| 1 国家 / 地区名称 | — | 解析时丢弃，见「去争议化」 |
| 2 CQ 区、3 ITU 区 | — | 本项目用不到 |
| 4 大洲 | `continent` | 两字母，直接采用 |
| 5 纬度 | `lat` | 正为北 |
| 6 经度 | `lon` | 文件里**正为西**，解析时取负 |
| 7 UTC 偏移 | — | 用不到 |
| 8 主前缀 | `dxcc` | 实体主键；带 `*` 的是 WAE 记录，整条丢弃 |
| 别名行 | `prefixes` | 逗号或空格分隔；`=` 开头的是完整呼号，不是前缀 |

大洲取文件字段，不由坐标反推：跨洲实体（夏威夷、加那利、土耳其的欧洲部分）按坐标推断会落到错误的一侧。大圆距离仍按坐标算，「数字区」（`BG7` 的 `7`）从呼号里取，二者运行时计算、不落地为字段。

两类记录不进入内存：

- **6 条 WAE-only 记录**，主前缀带 `*`（如 `*GM/s` 设得兰）。它们在 ARRL 赛事里计入母国实体，其中三条的别名全是 `=` 完整呼号，留下会得到零前缀实体。
- **19 条只有特设呼号的实体**（Conway Reef 只有 `3D2CCC`，Bouvet 只有 `3Y/LB5SH`）。生成器靠前缀拼呼号，留下它们只能编出数据源里不存在的呼号。

余下 321 个实体。

### 前缀命中怎么判

文件列的是**呼号开头**，不是「1–2 字母前缀表」：美国一条只有 `AA`–`AK`、`K`、`N`、`W`，因为 `KA1ABC`、`N6AA` 已经被 `K`、`N` 覆盖。所以「字母前缀是否命中」按三个方向判，任一成立即算命中：

| 情形 | 例子 |
|---|---|
| 精确等于某个 token | `BG` 命中 `BG` |
| 某个 token 以它开头 | `B` 命中 `BA` / `BD` / … |
| 它以某个 token 开头 | `KA` 命中 `K`、`IK` 命中 `I` |

第三个方向不能省：只判前两个方向，`KA`、`WA`、`IK` 这些真实前缀会被判成非法。

### 去争议化

文件带国家 / 地区名称，解析器不把它们带进内存：`DxccEntity` 只有 `dxcc` / `lat` / `lon` / `continent` / `prefixes` 五个字段，没有留放名称的位置。这与 [UI 设计](./UI.md) 的「不显示对方是谁」是同一件事——不是靠调用方自觉不去读，而是结构上读不到。

世界上合法的呼号前缀是**有限集合**，所以用完整表枚举、不用宽松正则。校验时前缀必须命中该表，再结合 ITU 格式判定整体合法性：基本为「1–2 字母前缀 + 数字 + 1–4 字母后缀」，但中国允许 `B` + 数字的无后缀异地 / 便携形式（如 `B5`），且可带 `/P`、`/M`、`/5` 等操作后缀（见 [QSO 协议](./QSO-PROTOCOL.md) 的「用户呼号」一节）。命中表只用来回答「格式对不对」，**不记录、不暴露该前缀属于哪个国家 / 地区**。

### 位置推断

- 根据呼号前缀查表得到坐标，用户的 QTH 用其自己呼号所属实体的质心
- 解析用户自己的实体时按**从长到短**的前缀匹配：先试 `B5`，查不到才退到 `B`——所以 `B5` / `B7` 归中国；`B` 本身不是表里的 token，只按单字母查会先命中斯普拉特利群岛的 `BM9S`。同一条规则也覆盖 `A5`、`E7`、`S5`、`T7`、`Z3` 等「单字母 + 数字」的呼号
- 前缀查不到（不在表内）时梯度无从计算，生成退回一个默认实体的普通呼号

## 虚拟 HAM 生成策略

### 生成优先级

用户决定（以 `BG7XXX` 为例）：匹配到对方虚拟 HAM 的可能性由高到低为——

1. **同根前缀 + 同数字区**（`B?7`，如 `BA7` / `BD7` / `BG7` / `BT7` / `BY7` / `BZ7`）：最高
2. **同根前缀（任意数字区）**（`B??`，如 `B?1` / `B?9`）：次高，即同实体 / 同国家
3. **地理邻近**（跨实体，按大圆距离）
4. **同大洲**
5. **其他**

> 说明：数字区匹配**始终以「根前缀（首字母）」为作用域**——`B?7` 必为中国（B 系）台，不会跨实体去匹配其他国家同样带数字 `7` 的前缀。因此「同数字区」天然落在同根前缀内，**不会跨国家**；`B??`（同根前缀、任意数字区）即等价于同实体 / 同国家。对前缀本身已含数字者（如 `VR2`），其数字区由前缀固定，不参与「同数字区」比较。

权重示例：

```text
同根前缀 + 同数字区（B?7）：100
同根前缀（B??，任意数字区）：40
地理邻近 < 3000 km：10
同大洲：5
其他：1
```

### 生成算法

两步抽取：**先按权重抽类别，再在类别内抽实体**（不是给每个候选算权重再轮盘抽——类别先定，才不会让"其他"这一档因为实体数量多而淹没邻近档）。

```text
1. 抽类别（权重 100 / 40 / 10 / 5 / 1，累计 156）
     CAT1 同实体 + 同数字区   B?7
     CAT2 同实体，任意数字区  B??
     CAT3 另一实体，大圆距离 < 3000 km
     CAT4 另一实体，同一大洲
     CAT5 其余
2. 在类别内随机取一个实体 → 取它的可用字母前缀
3. 拼「前缀 + 数字 + 2–3 个随机字母」，过一遍校验（ITU 格式 + 前缀表）

失败最多重试 50 次；仍失败（极不可能）则退回用户本实体的普通呼号。
```

> 距离用两坐标的大圆公式（haversine）算；「同一大洲」比的是 `continent` 字段。二者都只用到坐标与派生标记，不依赖任何国家 / 地区字段。用户的 QTH 用他自己呼号所属实体的质心近似。

### 呼号后缀生成

- 前缀确定后，随机生成后缀
- 例如 `BG7` 生成 `BG7XXX`，`JA` 生成 `JA1ABC`（后缀为随机字母，各次不同）
- 规则：字母前缀 + 1 位随机数字 + 2–3 位随机字母
- **不生成** `/P`、`/M`、`/5` 这类操作后缀——虚拟 HAM 一律是"在家电台"，构造简单，也让呼号校验只有一条路径

> 决策：虚拟呼号为练习用途，不校验是否真实存在、只判格式合法（见 [QSO 协议](./QSO-PROTOCOL.md) 的「用户呼号」）。因此后缀**纯随机生成**即可，无需为各地区维护精确格式，也**不**在解析结果里新增 `suffixPattern` 字段——以维持 `DxccEntity` 只含 `dxcc` / `lat` / `lon` / `continent` / `prefixes` 的去争议化纪律。

## 虚拟 HAM 运行时行为

> 实现（2026-10-14；2026-10-22 起改为持续呼叫）：本节的 CQ 行为、应答延迟与活跃数量已落地于 `src/ham/activity.ts` —— 纯逻辑，时钟与随机源全部注入、模块内无定时器。它由 `Frequency` 持有，界面层 `QsoSession` 以 1 s 驱动循环调用 `advance()`。
>
> **为什么由会话来定下一条 CQ 的时刻**：调度器不知道一条报文要发多久（那取决于 WPM、Farnsworth 和报文长度），只有会话知道。所以每次 `advance()` 报出一条 CQ 后，会话用 `scheduleNextCq()` 把下一次排到「这条报文发完 + 一个守听间隙」之后——慢手也不会被自己的下一条盖住。
>
> **环境独立于用户电台（2026-10-15）**：频段活动不是「用户开机才有」。应用启动时**每个波段各自**生成 **12–18 个台**并立即开始各自的 CQ 节奏（界面层为每个波段持有一个 `QsoSession`，自带驱动、互不相干）。用户的**开台 / 关台**只决定「是否接收当前波段」：关台时不接话、不发声、不发射，但频段照常运转——到点仍呼叫。因此「关台」不等于「清空」；同样地，切走波段再切回来，原波段仍是原来那批台。
>
> **台站有绝对频率（2026-10-15；2026-10-19 起散布到 ±25 kHz；2026-10-24 起落在任意 10 Hz）**：每个台生成时会被放置在一个**绝对频率**上——波段参考频率 ±25 kHz 之内、**以 10 Hz 为步长**（7.010.43、7.011.07……），而不是相对拨轮的位置。10 Hz 正是拨轮自己的最小步进（见 [界面](./UI.md) 的「滚轮调谐」），台站与操作者落在同一张刻度上。**从此不再保证台与台的间隔**：两台可能只隔几十赫兹、同时落在一个通带里——这正是真实波段的样子，那时两台的声音叠在一起，S 表读较强的那台，通联对象取离零拍最近的那台（见 [调谐与偏频](./AUDIO-ENVIRONMENT.md#调谐与偏频听到的音调)）。落点或呼号与同波段的台撞车（频率完全相同）时会重抽。这一个字段同时决定三件事：瀑布图上**画在哪里**（调谐时是窗口在动、台不动）、**听得清不清**（亮度/强度由它上报的 RST 推出）、以及**听不听得见**（超出拨轮 ±带宽/2 即被滤波器切掉）。
>
> **波段切片比屏幕宽（2026-10-19）**：台站散布在中央频率 **±25 kHz** 上（任意 10 Hz 位置），而瀑布窗口只有 **±10 kHz**。这不是缺陷，是刻意的：真实的频谱仪只能看到一段窗口，你**必须调谐才能遇到新台**——而电台页也不列名册，谁来谁走只能靠耳朵（见 [界面](./UI.md) 的「没有记录，也没有台名」）。
> 25 kHz 这个数顺带把「不出频段」钉死了：四个波段的默认中心 ±25 kHz 都恰好在频段边界之内（40m 7.000–7.050、20m 14.000–14.050 等）。

### CQ 行为

- **持续呼叫**：一条 CQ 发完，守听 **3 – 8 秒**，接着再发一条；台不离开频段，也不因为没人应就下线
- 因此**任何时刻调准一个台，都有很大概率立刻听到它**——听到的是它当前这条报文的后半段（见 [界面](./UI.md) 的「滚轮调谐」）
- 同一频段同时活跃 **12 – 18 个**，各自占一个频点（波段参考频率 ±25 kHz 内任意 10 Hz 位置；频率完全相同才算撞车，会重抽；显式调用 `seedHams(n)` 时以 n 为目标台数）。约合每 3 kHz 一个台：够你扫着找人，但**通带里偶尔会同时有两台**——它们同时出声，得靠音调与点名区分。

### 应答延迟

- 用户发 CQ 后，第一台虚拟 HAM 随机延迟 **1 – 5 秒**开口；多台应答时的错开规则见下方「多人应答（堆叠）」
- 用户应答虚拟 HAM 的 CQ 后，对方随机延迟 **1 – 3 秒**再回复

### 比赛模式下的台

比赛模式不改变波段上**有谁、在哪里、多久叫一次**，只改变它们说什么：

- **CQ 换成 `CQ TEST <呼号>`**：背景 CQ 与状态机的开场用同一个函数产出（见 [比赛模式](./CONTEST.md)），所以调过去听到的是比赛叫法，不是 `CQ CQ CQ DE … PSE K`。
- **报告恒 `5NN`**：难度只决定抄不清的概率，不再决定报告本身——比赛里没人报 `579`。
- **交换的数字是派生的，不是抽的**：CQWW 取该台呼号所属 DXCC 实体的 CQ 分区，WPX 由呼号哈希出一个三位序号。同一台在波段上待多久就发同一个号，生成器的随机序列一格不动。
- **旁边的两台仍然照日常那六行聊**：`sessionHamQso` 的脚本固定为 DX 形式，比赛模式下也一样。比赛频段里确实有人在闲聊，这不在本版改动范围内。

### 它会不会在你发射时守听

会，而且比真人还守规矩：

- **一开口通联，它自己的 CQ 就停了**（`band.markInQso`）。你回答它之后，它不会一边等你一边继续自顾自呼叫。
- **它按你的发报时长排队**：`userSend` 要等你这一整条报文发完（半双工尾巴也算）才进入 1–3 秒的答复延迟，所以它的回应永远落在你的 key 抬起之后，不会压在你身上。
- **它不会对你「聋」**：目前没有建模「两台同时发射谁都听不见」。现实里你打断别人时对方是抄不到的，这里对方仍然会收到——这是**简化**，不是 bug；要做的话得给虚拟台加一条与 `transmitting` 对称的 deaf 状态。

反过来说，**它只听它认得的那个呼号**。你发出去的每一行都要能让它决定「这是不是给我的」：点名了它、或者它正等着你的下一句，它才回；否则就是真实的沉默（没有解释，也无法追问），这正是训练器的目的。

### 你不出声的时候它会做什么

真实操作者不会对着空气说完一句就永远沉默：

- **发完一句等 10 秒**（比赛模式下只有 4 秒：跑起来的比赛没有慢慢抄的余地）。没等到你的下一句，就把上一条报文**原样重发**——和真人"再报一遍"一样，不换措辞（比赛里那句重发是 `5NN <我的号>`，就是它自己的报告）。
- **最多重发 3 次**（`PARTNER_REPEAT_LIMIT`）。仍无人应，就结束这次通联，该台回到自己的 CQ 周期（隔 3–8 秒重新呼叫）。界面上记一条「对方呼叫几次没人应，已回到 CQ」。
- **你一开始发报，计时就重新开始**；正在发报时它不会插话。关台期间同样暂停计时，开机后重新给满一次。
- 这条规则只在你和它已经通联（`EXCHANGE` / `SIGNOFF`）时生效；它在喊 CQ 时本来就有自己的节奏（见上方「CQ 行为」）。

> 实现：`src/ui/sessionPatience.ts` 的 `Patience.servicePartnerWait` 驱动状态机的 `timeoutResend()`，与同一处的 `Patience.expireOwnCq` 驱动 `timeoutFirstCall()` 是同一种接法——两个时钟都由会话的每秒 tick 推进，自己不用定时器。

### 接收不全

- 概率由难度档决定：新手 **0%** / 进阶 **1%** / 硬核 **5%**（`MISS_PROBABILITY`）
- 触发时虚拟 HAM 发 `AGN?`（请求全文重发；`QRZ?` 专用于呼号抄错，不在此用）
- 要求用户全文重发
- 不模拟具体丢失内容

### 行为约束

- 虚拟 HAM 不会在后续阶段发 `PSE K`
- 虚拟 HAM 不会主动违反通联协议
- 用户发 `PSE K` 在后续阶段，虚拟 HAM 正常回应，不视为错误
- 虚拟 HAM 在呼号已确认、进入可省略阶段后，交还发言权一律用 `BK`（不用纯 `K`），向对方发出「可省略呼号」信号（见 [QSO 协议](./QSO-PROTOCOL.md) 的「收发基线」）
- 虚拟 HAM 回应 / 确认用户报文时，于报文起始加 `R`（收到确认）；例外：首次应答 CQ（给出本方呼号、建立通联）不带 `R`（见 [QSO 协议](./QSO-PROTOCOL.md) 的「收发基线」与「R（收到确认）」）

### 两类虚拟 HAM：呼叫台与应答台

频段上同时存在两种台，**而只有一种会出现在频谱上**：

|  | 呼叫台（caller） | 应答台（answerer） |
| --- | --- | --- |
| 做什么 | 定时发 CQ，等别人来应 | 只应别人的 CQ，**从不主动发 CQ** |
| 有没有频率 | 有。±25 kHz 内的一个 10 Hz 频点 | **没有**。只在开口的那一刻，落在被应答者的频率上 |
| 看不看得见 | 看得见（瀑布图） | **看不见**——除非它正在回答你 |
| 数量 | 12–18 台，受频谱容量限制 | **80–120 台**（`ANSWERER_POOL_MIN/MAX`），与频谱容量无关 |

守听是不发射的，所以频谱仪上本来就没有它们的位置：**能不能看到一台台，取决于它有没有在发射，而不是它存不存在**。真实波段上守听的人远多于同时发报的人——这条常识在模型里就是「应答台的数量远超频谱的容量」。

> **实现（2026-10-19）**：`src/ham/answerers.ts` 的 `AnswererPool`（按需生成、用完归还）+ `VirtualHam.role`。池子里的台**不进入** `HamActivity` 名单，因此不占频点、不出现在瀑布图里；只有正在发射时，`QsoSession.spectrum()` 才把它们画在拨轮那个位置上。

两类台在两种场合相遇：

1. **你发 CQ** → 2–3 台应答台从池子里出来应你（见下方「多人应答（堆叠）」）。它们不占频段上的位置；点名之后，其余的回池子。
2. **某个呼叫台发 CQ** → 一台应答台来应它（见下方「互相通联（后台）」）。通联期间它待在那台的频率上，说完 `73` 就回池子——**它从来没有自己的频点，所以也没有「回到原位」这回事**。

### 多人应答（堆叠）

> **已实现（2026-10-19）**：`src/ham/pileup.ts`（纯逻辑）+ `QsoSession` 调度。替换原先「第一版只允许一个台应答」的占位。

- 用户发 CQ 后，**2 – 3 台**先后应答；第一台仍在 **1 – 5 秒**内开口，后续各台在前一台报完呼号后再隔 **0.5 – 1.5 秒**，形成堆叠而不是齐射。
- **所有应答者都落在呼叫者的拨轮频率上**（CW 堆叠里大家零拍同一个目标），因此它们同时是瀑布图上的同一根亮柱。应答者来自**守听池**，不占频段名额：你发一次 CQ，波段上的台数不会因此多出两三台。
- 每台报完自己的呼号后**静默 3 – 7 秒**再重呼，间隔各自独立抽取，用来把各台岔开（单声道音频一次只播一台）。
- **必须点名**：用户回复里出现某台的呼号，该台即为通联对象，其余各台离场；被点名者隔 1 – 3 秒回 `R UR RST 599 BK`，进入正常交换流程。
- **不点名不推进**：`R BK` 之类没有呼号的回复不会被任何一台认领，各台重新抽取静默后继续等待；界面会记一条「没有点名任何一台」。
- **点名别人就等于离开这轮堆叠**：回复里出现一个**不在应答名单里的呼号**（比如你调过去回答了波段上另一台的 CQ），说明你已经转去通联别人，这轮堆叠立即作废，那句话按正常通联送出去，不再当成「没点名」吞掉。判据只看「这一行里有没有呼号」，见 `QsoSession.userSend`。
- 每台最多重复 **4 次**；都没被点名则依次消失（回到守听池——它们从未占用频段，所以也不是「下线」）。
- **自己的 CQ 有耐心上限**：堆叠散尽后仍没人被点名，**15 秒**内没有下文就回到守听（`Patience.expireOwnCq`，对应状态机的 `timeoutFirstCall`），界面记一条「没有人回应你的呼叫」。否则状态机会一直停在 `USER_CQ`，之后你回答别人的 CQ 会被它当成「还在等我呼叫的回应」而石沉大海——屏幕有声、对方永远不开口，且没有任何解释。
- 关台时不发 CQ，也不会产生堆叠；堆叠状态不写入暂存，刷新即失去（已完成的通联不受影响）。

> **没有「网格」，也没有间距约束**：波段上的台可以彼此靠得很近，应答者按定义就在你的频率上。两台同时可听时，「谁在应我」由**点名**决定；没点名时取离零拍最近的那台。这不是漏洞：真实波段上两台叠在一起是常事，靠音调与呼号分开才是要练的本事。

### 互相通联（后台）

> **已实现（2026-10-19）**：`src/ham/hamQso.ts`（纯逻辑）+ `QsoSession` 调度。它取代了第三步留下的「两个 AI HAM 之间通联」预留。

- **随机发生**：每个波段每 **30 – 90 秒**尝试一次。前提是这一波段**至少 3 台**——两台互连，还要至少留一台给操作者；已在通联中的台不参与，优先挑一台**正在呼叫 CQ** 的台当呼叫方（现实里就是有人应了正在发的 CQ）。
- **同频，但只有一台占着频率**：呼叫方是频段上的台（占着一个频点），应答方是**从守听池里出来的**——它没有自己的频点，通联期间就待在这个频率上。所以操作者只要把拨轮停在那台上，就能同时听到两边；瀑布图上因此也只有一根亮柱。说完 `73` 后应答方**回池子**（它从未占过频率，也就没有「回原位」这回事），呼叫方继续呼叫。
- **脚本**：就是 QSO 协议里的标准 **6 行**（CQ → 应答 → RST → RST → 73 → 73），按操作者设定的速度逐行播出，两次发射之间留 **0.6 – 1.6 秒**。
- **不能插话**：两台的 `inQso` 状态使它们不会成为「可通联对象」，也不会应答操作者的呼叫。操作者在这个频率上**发 CQ 也没人理会**——正在通联的人不会丢下对方去应一个陌生呼叫，所以不会生成任何堆叠应答，操作者也得不到任何解释（见下条）。发报同理：没有通联对象时按键就是没反应。
- **对操作者不可见（2026-10-19 修订）**：真实情况下**你看不到**别人是否在通联——你只能调到那个频率去听。因此界面上**没有任何提示**：没有名册可以标注这一对，瀑布标签不显示，也没有「调过去旁听」。唯一的线索就是调过去以后听到的报文。在这个频率上发 CQ **不会被拒绝、也不会给解释**：CQ 照常发出去，然后**没有人应答**——这正是真实操作者在这种情况下的全部感受。
- **签完 73 后呼叫方继续呼叫**：通联结束时，原来发 CQ 的那台**隔 2 – 6 秒重新呼叫**，应答方**回守听池**。于是操作者调到这个频率会听到：两句 `73 SK`，短促的安静，然后又是 `CQ CQ CQ DE ...`——**这就是"等它们通联完了再上去"的入口**，此时可以正常应答它。
- **环境属性**：关台或切到别的波段时照常发生、照常推进脚本，只是听不到；操作者自己有通联或堆叠时**不插入**（单声道音频会互相切断）。通联不写入暂存，刷新后是新的一轮。
