# 比赛模式（CQWW 与 WPX）

> 本文件描述**比赛模式**：三种模式的差别、交换的那个数字从哪来又长什么样、一次比赛通联怎么走、录入行的多出来的格子、日志里的「核对」与「重复」、三本账如何分开，以及场次的边界。
> 相关：报文文件与录入行的通用规则见 [快速报文与日志录入](./MESSAGES.md)；状态机与报文格式见 [通联过程](./QSO-PROTOCOL.md)；日志字段与存储见 [日志与存储](./LOG.md)；界面上的模式选择器见 [界面](./UI.md) 的「电台风格外壳」。

---

## 三种模式

电台顶栏上有一个**通联模式**选择器：`DX` / `CQWW` / `WPX`。它们不是三种玩法，而是**同一套流程里交换的东西不同**——DX 只交换呼号与 RST，比赛在报告后面再挂一个数字。

| 模式 | 空中的交换 | 我方数字从哪来 | 日志里的额外列 |
|---|---|---|---|
| `DX` | 呼号 + RST | 无 | 无 |
| `CQWW` | 呼号 + RST + **CQ 分区** | 本方呼号所属的 DXCC 实体（`cty.dat`）；设置里可以覆盖 | `EXCH_RX` / `EXCH_TX` |
| `WPX` | 呼号 + RST + **自增序号** | 设置里的当前序号，每记一条日志加一；录入行里那一格可以当场改 | `EXCH_RX` / `EXCH_TX` |

一条规则贯穿两个比赛：**比赛里的报告恒为 599**（空中写作 `5NN`）。日常模式里虚拟台会按难度给出 `579`、`559` 这样有起伏的报告；比赛里没人一边跑一边校准可读性，所以对方发来的一律是 `5NN`，核对时也按 599 比——这一点在 [通联过程](./QSO-PROTOCOL.md) 的状态机里是一个分支，不是概率。

我方那一格（`我方 RST`）默认也是 `599`，但留着可改：练习者想练"抄一个 579"或者故意报低，改了就照改的发、日志也照改的记。程序不强制——真实比赛里 599 是惯例，不是规则。

模式决定三件事，别的都不变：**空中的措辞**（报文文件里的八个键与状态机的固定语句）、**`{EXCH}` 的值**、**日志记到哪一本**。频段、台站、堆叠、互连、音频环境全部照常——比赛模式不改变波段上有什么，只改变你要说的话。

## 交换的那个数字

### 它有多长

两个比赛都不规定位数，**规定的是上限**：CQWW 的分区最多两位（1–40），WPX 的序号最多六位——真实比赛里一个周末也到不了千位以上，六位是录入框的边界，不是规则的重点。

- **补不补前导零，是各台自己的习惯**：5 区可以发 `05`，也可以发 `5`。程序里有些虚拟台补、有些不补，两种都得抄得下来。
- **用不用简码，也是自己的习惯**：`05` 可以发 `05`、`T5`、`5`，收报一侧都认（短码表见 [快速报文与日志录入](./MESSAGES.md) 的「宏」）。
- **收报一侧只认数**：抄到 `5`、`05`、`T5` 都是同一个数，前导零听漏了不算抄错。录入框里只收数字——简码是**发**的写法，不是**记**的写法。
- **日志里记的永远是不带前导零的数字**：`5`、`1`。空中的 `TTA`、`05` 都是它的一种写法，账本只记那个数。
- **抄到多少位就记多少位**：虚拟台的 WPX 序号最多三位（`1`–`999`），但操作者写 `12345` 也不会被拦——那是你抄下来的东西，不对劲由「核对」去说，不归录入框管。

### 我方发出去的

- **CQWW 的分区**：默认取本方呼号命中的 DXCC 实体（`cty.dat`）所带的 CQ 分区，一个都匹配不到时按 **24 区**（本程序的示例台 `BG7XXX` 所在）。设置里有**「覆盖 CQ 分区」**，留空就是不覆盖——分区是"你在哪儿"，不是每通一个台换一次的号。设置面板里会写出"现在是 N 区"。
- **WPX 的序号**取自设置（`WPX 下一个序号`），从 `1` 起，**每记录一条日志加一**。加到哪一条都算——**核对出来是错的也照样加**：真实比赛里那个号已经发出去了，收不回来，下一台照样是下一个号。
- 发出去时默认补位（分区两位、序号三位），因为 CW 里前导零正好可以用短码写成一个字母 `T`（`001` 在通联时是 `TTA`），比全码短得多。想发不补位的号，把录入行里「我方序号」那一格改成 `12` 就行——**那一格里的字是什么，空中就是什么**。

## 一次比赛通联

### 主叫（Run）

以主叫方 `BG7XXX`（中国，**24 区**）与应答方 `JA1ABC`（日本，**25 区**）为例：

| 步骤 | 谁 | 报文 | 操作者在做什么 |
|---|---|---|---|
| 1 | 我 | `CQ TEST BG7XXX` | 按 F1。比赛里不报 `DE`、不发 `PSE K` |
| 2 | 对方 | `JA1ABC` | 抄呼号，写进录入行第一格 |
| 3 | 我 | `JA1ABC 5NN U4` | 按 F2（`{THEIRCALL} {RST} {EXCH}`）：点名 + 报告 + 我方分区，一句话说完 |
| 4 | 对方 | `R 5NN U5` | 抄两个数字（`R` 可发可不发；对方也许发 `25`、也许发 `5`，那不是我方的事） |
| 5 | 我 | `TU` | 按 F3 把这句发出去，再按回车落账（先按 F3、后按回车，回车不会再发一遍 `TU`） |

第 3 步是主叫最省事的地方：**报告那一句自带对方呼号**，点名、报告、交换一句话说完，所以抄清呼号之后高亮直接跳到 F2。日常通联在这里要先单独回一次自己的呼号（`{MYCALL}`），比赛的主叫省掉这一轮。

### 应答（S&P）

调到一个正在 `CQ TEST` 的台，顺序与日常通联一样——**先报自己，再报报告**：

| 步骤 | 谁 | 报文 | 操作者在做什么 |
|---|---|---|---|
| 1 | 对方 | `CQ TEST JA1ABC` | 守听，抄下呼号，写进录入行第一格 |
| 2 | 我 | `BG7XXX` | 按 F4（`{MYCALL}`）：**只报自己的呼号**——比赛里没人有空带上对方的呼号 |
| 3 | 对方 | `BG7XXX 5NN U5` | 只抄那个分区——两个 `599` 光标一到就已经填好了。他连我方呼号一起报，就是确认叫的是你 |
| 4 | 我 | `JA1ABC 5NN U4` | 按 F2：报告 + 我方分区 |
| 5 | 对方 | `TU` | 收工，按 F3 落账 |

**第 2 步省不掉**：那个台在听见你的呼号之前不知道是谁在叫它，报告不可能是它听见的第一句——不管这场比赛叫 CQWW 还是日常 DX。主叫没有这一步，是因为主叫一直在等别人来叫它。

**但这一句比日常短**：日常是 `JA1ABC DE BG7XXX`（点名对方 + `DE` + 自己），比赛只有一个 `BG7XXX`。抢着报自己是谁，是比赛应答的全部礼节。

这两条路是同一条梯子上的两个入口，[快速报文与日志录入](./MESSAGES.md) 的「高亮与回车」把四级写在一起。

与日常通联的差别只有六处，全部由模式决定：

- **CQ 是 `CQ TEST`**：状态机的开场、八个键里的 F1、以及波段上其他台的背景 CQ 都用同一份措辞（`qso/contest` 的 `cqText`），所以调到哪一台听到的都是比赛叫法。
- **报告恒 `5NN`**：对方发的、我发的、核对时比的都是它。
- **F2 带对方呼号**（`{THEIRCALL} {RST} {EXCH}`）：一句话完成点名与交换。它是比赛里按得最多的键。
- **F6 是重发键**（`{RST} {EXCH} {EXCH}`）：对方没抄清时把报告再报一遍、数字连发两遍。只差数字时也可以先问一句 `NR?`（F8）。
- **交换数字跟在报告后面**，不是单独一步：`5NN 05` 是一句话，抄的时候也是连着抄。
- **收尾只有 `TU`，没有 `73`、没有 `SK`**：比赛里的通联到 `TU` 就结束。状态机在比赛模式下把 `TU` 直接判成通联完成（`LOGGED`），不再要求双方各发一句结束语。但在收尾状态里发一句 `?` 或对方的呼号**不算**收尾——只有 `TU` / `73` / `SK` 才算。

> 反过来，日常模式的规矩一条不少：抄错呼号对方仍回 `QRZ?`，数字没抄清对方问 `NR?`（日常模式下是 `AGN?`）。**对方等不到你开口的耐心**：比赛 **4 秒**，日常 10 秒；两种模式都一样——重发三次仍没人应，它就回自己的 CQ，不再等你。比赛只换了用词和交换内容，没有放松对错——节奏还更紧，所以新手往往要靠其中一次重发才能把数字抄全。

## 录入行

比赛模式下录入行比日常多格子，顺序就是抄收的顺序：

| 模式 | 格子 |
|---|---|
| `DX` | 对方呼号 / 我方 RST / 对方 RST |
| `CQWW` | 对方呼号 / 我方 RST / 对方 RST / **对方 CQ 分区** |
| `WPX` | 对方呼号 / 我方 RST / 对方 RST / **我方序号** / **对方序号** |

- **两个 RST 在比赛里都是已知的**：不管主叫（Run）还是应答（S&P），取一步就把两个都填成 `599`（你改过就保留你的），WPX 还会把「我方序号」填上，光标直接跳到**对方的那一格**。所以比赛里真正要抄的只有那个数字：S&P 下按完 F4（报名）光标就已经等在对方那一格，抄下、回车，F2 把你的报告发出去；Run 下抄清呼号按回车，同样落在这儿。想要别的报告就自己改——`599` 只是默认值，不是不许改。
- **我方序号那一格留空就发设置里的下一个号**（占位符里显示的就是它）。想发 `12` 而不是 `012`，直接改这一格——它改的是**这一次**发的号，不会改动设置里的计数器。
- **CQWW 不显示我方分区**：分区是"你在哪儿"，在设置里改一次就定了。显示在录入行只会多一个要看的地方。
- **抄到的数字只收数字**：分区框两位、序号框六位就到头；简码不往框里写。
- **抄回 `5`、`05`、`005` 都算同一个数**（见下方「核对」）。

> 交换数字**不参与状态机**：抄错一个分区，对方不会回你一句"错了"——它也不知道你抄错了。空中会被纠正的只有呼号（`QRZ?`）与数字（`NR?`）。所以分区 / 序号抄得对不对，只有事后这一列敢说。

## 核对：错在哪一项

日志多一列**核对**，说的是**这条抄得对不对**（另一列「重复」说的是"是不是又通了一次"，见下文），取值只有四种：

| 显示 | 含义 |
|---|---|
| `正确` | 呼号、交换信息、RST 都抄对了 |
| `呼号错误` | 呼号不是那个台——这条按另一次通联记了 |
| `交换信息错误` | 呼号对，交换信息抄错了 |
| `RST 错误` | 前两项都对，只有报告抄错了 |
| `—` | 没有与该台的收发过程可比（手记的条目） |

判定顺序就是**先呼号、再交换信息、再 RST**：呼号错了，后面两项判不判都没有意义——那已经是另一个台了，所以只报「呼号错误」。

两个前提值得写下来：

- **核对用的是"对方真正发了什么"**，在落账那一刻读取。先按 F3 把 `TU` 发出去、再按回车落账，并不影响这件事——对方被放回波段只是回去发自己的 CQ，它发过什么都还记着。手记的条目没有这个对象，所以永远没有核对结果，而不是"假定正确"。
- **只说错在哪一项，不给正确答案**。这与整页「不显示对方是谁」是同一条原则：一旦把正确的分区印在屏幕上，抄收就从"听"变成了"读"。所以核对列是一句判决，不是一个纠错建议——要不要回去再问一遍（F6 或 F8），是操作者的判断。
- **改过的记录丢掉核对结果**：核对是对"当时抄下来的那一份"下的判断，行被编辑过，被判断的那一份就不存在了（程序不保留原件）。编辑时交换信息两格只收数字，不会再存进一个 `abc`。

## 三本账

三种模式各自一本日志，互不混淆：日常通联与比赛通联不是同一种记录，CQWW 的分区与 WPX 的序号也不是同一种数字。

- 日志页顶部是三个标签（`DX n` / `CQWW n` / `WPX n`，`n` 是该本的条数），点哪个看哪个。**编辑、删除、清空都只作用于当前标签**。比赛的标签只数**当前这一场**（DX 没有场次，数全部）。
- 单独删一行在每行末尾的「删除」，同样**点两次**。
- 清空是**点两次**：第一次只把按钮换成「再点一次清空 N 条，不可恢复」，第二次才真删。日志不能导出、删了也找不回来，所以这里不许一次点完。跨三本的「清空全部日志」一直在页面上（有记录时就看得见），也点两次。
- 切换通联模式时，日志页跟着跳到那一本——正在做比赛的人默认想看比赛账。

日志字段、写入条件与存储方式见 [日志与存储](./LOG.md)。

## 场次：一场的边界由自己划

真实比赛有起止时间：周六 00:00 UTC 开始，周日 24:00 结束。练习器没有这个钟——你什么时候想练就什么时候开，练多久都行。所以边界的意义从"时间"换成了"这一本账从哪儿开始数"。

- 日志页的比赛标签下多一行：**`本次 n` / `历史 m`**，加一个「开始新的一场」。
- **「开始新的一场」把这一本整体转入历史**：之后记的每一条都属于新的一场，旧的一本原样留着，随时翻回去看。**日志一条都不删**——这不是清空，是划线。
- **两个比赛各划各的线**：在 CQWW 上换场，WPX 那一本还在原来那一场。场次是账本自己的属性，不是机器的属性。
- **换场时 WPX 的序号回到 `1`**：新的一场从头数。设置里也能手动改回去，两种都行。
- **换场等于承认这次通联结束了**：如果正打到一半，正在填的那一行会清空（和切模式一样）。
- **正在写的那一场是默认视图**：页面上显示的就是"现在"。翻到「历史」是去看，回去点「本次」就回来；换标签、换场、换模式都会回到「本次」。
- **清空按钮只清屏幕上这一批**：在「本次」清本次，在「历史」清历史。

> 场次只是这本账上的一个分组，**它不筛选、不阻塞任何东西**：落账永远只看录入行填没填全（见 [日志与存储](./LOG.md) 的「写入条件」），与你在第几场无关。

## 重复通联：标出来，但通联照样做完

比赛里最常做的一件事：调到一个正在 CQ 的台，通完一半才想起"这个我好像通过"。

程序的处理和真实操作一样——**只标记，不打断**：

- 日志里多一列**重复**。判定是「**同一场 + 同一波段 + 同一呼号**」，已经记过就标`重复`。
- **判的是波段，不是频率**：14.0251 通一次、14.0317 再通一次，算重复；换到 7 MHz 就是新的一次。
- **不拦通联、不拦落账**：交换照做、`TU` 照发、那一行照记。真实情况下你也不会因为"好像通过了"就装作听不见——这是礼貌，也是操作纪律。
- **先通的那条不标**：标的是后一次。所以同一个台通了三次，有两条带 `重复`。
- 标记是**画页面时算出来的**（`ui/logDupes`），不写进存储：改了频率或呼号，标记自然跟着变，不会留下一个"当时算过"的死结论。

## 切模式时发生什么

模式选择器在顶栏左侧（`DX` / `CQWW` / `WPX`），**关台时也能改**——换的是"要说什么"，不是收发机。

- **换模式 = 放弃正在进行的这次通联**：措辞变了、交换的数字也变了，把一次通联跨越这个切换带下去，等于半句日常通联接半句比赛通联。所以会话重置、录入行清空，从头开始。
- **波段也整块换掉**：模式不只决定你要说什么，也决定**台上的台说什么**（`CQ JA1ABC` 与 `CQ TEST JA1ABC`）。所以换模式时重新放置虚拟台——旧的台全部下台，瀑布图清空，按新措辞起一批新台（呼号也是新的）。这比让正在发的台"改口"干净，也更接近"我换了一场比赛"。调谐频率不跟着变：换的是台上是谁，不是你在哪。
- 八个功能键换一份报文：桌面版是 `app-data/messages/` 下的 `DX.msg` / `CQWW.msg` / `WPX.msg` 三个文件，浏览器版用打包进去的对应默认（见 [快速报文与日志录入](./MESSAGES.md) 的「模式配置文件」）。
- 交换的数字与报文是两回事：改设置里的分区 / 序号**不会**重置会话，正在进行的通联照旧——那是"我发什么号"，不是"我在做什么模式"。

## 不做什么

比赛模式刻意停在这几件事之前：

- **不计分、不算系数、不做多波段统计、不模拟 10 分钟换频这类规则**。这个程序的产物是一本练习账，不是一份可提交的成绩单（日志不可导出，见 [日志与存储](./LOG.md)）。
- **不模拟"整个波段都在比赛"**：波段上的台仍按日常的节奏发 CQ、堆叠、互连，只是把措辞换成了比赛用语、交换里多了那个数字。所以调过去听到的不会是密不透风的比赛频段，而是稀疏的、像样的几个台。
- **不校验"这个台是不是真的在参加这场比赛"**：任何台问它分区 / 序号都会给。真实比赛里确实也有不参加的人，这里不做区分。
- **虚拟台的 WPX 序号最多三位**：它由呼号派生，落在 `1`–`999` 之间，所以真实 WPX 后半程那些 `1xxx` 这一版练不到。但这只是"练不到"，不是"抄错了"——录入框收得下六位，你抄到多少就记多少（见上文「它有多长」）。
- **不做跨波段的重复判断**：同一台在这个波段通过、那个波段还没通过，就是两次有效的通联。
- **`EXCH_TX` 记的是「我方序号」那一格的字**（CQWW 没有这一格，记的是设置里的分区）。那一格通常由程序按计数器填好，你改过就记改过的——它记的是这一行实际发出去的那个数。中途去设置里改分区 / 序号只影响之后的行，不动已经填好的这一行。
- **旁边的两台仍在说日常通联那六行**（`sessionHamQso` 的脚本固定为 DX 形式），比赛模式下也一样。听到有人在比赛频段里慢慢聊，是真实的；另写一套比赛脚本不在这版范围内。
