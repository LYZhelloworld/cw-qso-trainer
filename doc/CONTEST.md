# 比赛模式（CQWW 与 WPX）

> 本文件描述**比赛模式**：三种模式的差别、交换的那个数字从哪来、一次比赛通联怎么走、录入行多出来的那一格、日志里的「核对」与「重复」、三本账如何分开，以及场次的边界。
> 相关：报文文件与录入行的通用规则见 [快速报文与日志录入](./MESSAGES.md)；状态机与报文格式见 [通联过程](./QSO-PROTOCOL.md)；日志字段与存储见 [日志与存储](./LOG.md)；界面上的模式选择器见 [界面](./UI.md) 的「电台风格外壳」。

---

## 三种模式

电台机头上有一个**通联模式**选择器：`DX` / `CQWW` / `WPX`。它们不是三种玩法，而是**同一套流程里交换的东西不同**——DX 只交换呼号与 RST，比赛在报告后面再挂一个数字。

| 模式 | 空中的交换 | 我方数字从哪来 | 日志里的额外列 |
|---|---|---|---|
| `DX` | 呼号 + RST | — | 无 |
| `CQWW` | 呼号 + RST + **CQ 分区**（1–40，两位） | 设置里的分区；填 `0` 就按本方呼号的 DXCC 实体推断 | `EXCH_RX` / `EXCH_TX` |
| `WPX` | 呼号 + RST + **自增序号**（1–9999，三位） | 设置里的当前序号，每记一条日志加一 | `EXCH_RX` / `EXCH_TX` |

一条规则贯穿两个比赛：**比赛里的报告恒为 599**（空中写作 `5NN`）。日常模式里虚拟台会按难度给出 `579`、`559` 这样有起伏的报告；比赛里没人一边跑一边校准可读性，所以对方发来的一律是 `5NN`，核对时也按 599 比——这一点在 [通联过程](./QSO-PROTOCOL.md) 的状态机里是一个分支，不是概率。

我方那一格（`我方 RST`）默认也是 `599`，但留着可改：练习者想练"抄一个 579"或者故意报低，改了就照改的发、日志也照改的记。程序不强制——真实比赛里 599 是惯例，不是规则。

模式决定三件事，别的都不变：**空中的措辞**（报文文件里的八个键与状态机的固定语句）、**`{EXCH}` 的值**、**日志记到哪一本**。频段、台站、堆叠、互连、音频环境全部照常——比赛模式不改变波段上有什么，只改变你要说的话。

## 交换的那个数字

### 我方发出去的

- **CQWW 的分区**取自设置（`CQ 分区`），填 `0` 表示"按呼号自动推断"，也就是用本方呼号命中的 DXCC 实体所带的 CQ 分区；一个都匹配不到时按 **24 区**（本程序的示例台 `BG7XXX` 所在）。设置面板里会直接写出"现在会发 N 区"。
- **WPX 的序号**取自设置（`WPX 下一条序号`），从 `001` 起，**每记录一条日志加一**。加到哪一条都算——**核对出来是错的也照样加**：真实比赛里那个号已经发出去了，收不回来，下一台照样是下一个号。设置里可以改、也可以一键回到 `1`。
- 两个数字都**补位再发**：分区两位（`5` → `05`），序号三位（`1` → `001`）。补位不是为了好看——CW 里前导零正好可以用短码写成一个字母 `T`（见 [快速报文与日志录入](./MESSAGES.md) 的「宏」），`001` 在空气中是 `TTA`，比 `001` 短得多。短的先后顺序决定了比赛里报文的节奏。
- **补位与短码只发生在空中**：录入行里显示、日志里记的永远是 `05`、`001` 这样的数字。

### 对方发来的

两个比赛都不抽随机数，而是**从既有数据派生**：

- **CQWW**：取该台呼号所属 DXCC 实体的 CQ 分区——这正是真实 CQWW 日志里那一列数字的来历。
- **WPX**：由呼号哈希出一个三位号。同一台在波段上待多久就发同一个号（真实比赛中那个号是它的通联计数，不是每句换一个），而生成器的随机序列一格都没动——这是本项目一贯的 RNG 纪律（见 [虚拟 HAM 策略](./VIRTUAL-HAM.md)）。

## 一次比赛通联

以主叫方 `BG7XXX`、应答方 `JA1ABC`、CQWW 24 区发给对方 5 区为例：

| 步骤 | 谁 | 报文 | 操作者在做什么 |
|---|---|---|---|
| 1 | 我 | `CQ TEST BG7XXX` | 按 F1。比赛里不报 `DE`、不发 `PSE K` |
| 2 | 对方 | `JA1ABC` | 抄呼号，写进录入行第一格 |
| 3 | 我 | `JA1ABC 5NN 05` | 按 F2：报告 + 我方分区 |
| 4 | 对方 | `R 5NN 05` | 抄两个数字（`R` 可发可不发） |
| 5 | 我 | `TU` | 按 F3，这一行落账 |

与日常通联的差别只有五处，全部由模式决定：

- **CQ 是 `CQ TEST`**：状态机的开场、八个键里的 F1、以及波段上其他台的背景 CQ 都用同一份措辞（`qso/contest` 的 `cqText`），所以调到哪一台听到的都是比赛叫法。
- **报告恒 `5NN`**：对方发的、我发的、核对时比的都是它。
- **应答别人的 CQ 只报自己的呼号**（F4 = `{MYCALL}`）：比赛里不重复对方呼号、也不说 `DE`，一个呼号就够。
- **交换数字跟在报告后面**，不是单独一步：`5NN 05` 是一句话，抄的时候也是连着抄。
- **收尾只有 `TU`，没有 `73`、没有 `SK`**：比赛里的通联到 `TU` 就结束。状态机在比赛模式下把 `TU` 直接判成通联完成（`LOGGED`），不再要求双方各发一句结束语。

> 反过来，日常模式的规矩一条不少：抄错呼号对方仍回 `QRZ?`、报告抄不全仍回 `UR RST?`、对方等不到你开口仍会在 10 秒后重发。比赛只换了用词和交换内容，没有放松对错。

## 录入行多一格

比赛模式下录入行是**四格**：对方呼号、我方 RST、对方 RST、**对方的分区 / 序号**（`对方CQ 分区` / `对方序号`）。前三格的含义与日常模式完全一样，见 [快速报文与日志录入](./MESSAGES.md) 的「录入行」。

- **第四格不是独立的一步**，它是随对方报告一起来的那个数字。所以高亮与回车的步骤仍是那四步（呼号 → 回呼号 → 报告 → 收尾），只有"能不能落账"多了一个条件。
- **框会限制位数**：分区两位、序号四位——填不进一个永远不合法的数。
- **我方那个数字显示在 Run / S&P 旁边**（`我方 24`、`我方 007`）。它在设置里，不在这行上，如果也不显示出来，操作者就看不见自己正在发什么号。记完一条之后读数立刻变成下一个号：屏幕上那个就是下一句话要发出去的。
- **抄回 `5`、`05`、`005` 都算同一个数**：前导零听漏了不算抄错（见下方「核对」）。

## 核对：错在哪一项

**交换数字不参与状态机**：抄错一个分区，对方不会回你一句"错了"——它也不知道你抄错了。空中会被纠正的只有呼号（`QRZ?`）与报告（`UR RST?`）。所以分区 / 序号抄得对不对，只有事后这一列敢说。

日志多一列**核对**，说的是**这条抄得对不对**（另一列「重复」说的是"是不是又通了一次"，见下一节），取值只有四种：

| 显示 | 含义 |
|---|---|
| `正确` | 呼号、交换信息、RST 都抄对了 |
| `呼号错误` | 呼号不是那个台——这条按另一次通联记了 |
| `交换信息错误` | 呼号对，分区 / 序号抄错了 |
| `RST 错误` | 前两项都对，只有报告抄错了 |
| `—` | 没有与该台的收发过程可比（手记的条目） |

判定顺序就是**先呼号、再交换信息、再 RST**：呼号错了，后面两项判不判都没有意义——那已经是另一个台了，所以只报「呼号错误」。

两个前提值得写下来：

- **核对用的是"对方真正发了什么"**，在落账那一刻读取（对方还没被放回波段之前）。手记的条目没有这个对象，所以永远没有核对结果，而不是"假定正确"。
- **只说错在哪一项，不给正确答案**。这与整页「不显示对方是谁」是同一条原则：一旦把正确的分区印在屏幕上，抄收就从"听"变成了"读"。所以核对列是一句判决，不是一个纠错建议——要不要回去再问一遍（F6），是操作者的判断。
- **改过的记录丢掉核对结果**：核对是对"当时抄下来的那一份"下的判断，行被编辑过，被判断的那一份就不存在了（程序不保留原件）。

## 三本账

三种模式各自一本日志，互不混淆：日常通联与比赛通联不是同一种记录，CQWW 的分区与 WPX 的序号也不是同一种数字。

- 日志页顶部是三个标签（`DX n` / `CQWW n` / `WPX n`，`n` 是该本的条数），点哪个看哪个。**编辑、删除、清空都只作用于当前标签**。
- 单独删一行在每行末尾的「删除」。
- 清空是**点两次**：第一次只把按钮换成「再点一次清空 N 条，不可恢复」，第二次才真删。日志不能导出、删了也找不回来，所以这里不许一次点完。全部清空（跨三本）另有一个按钮，同样点两次。
- 切换通联模式时，日志页跟着跳到那一本——正在做比赛的人默认想看比赛账。

日志字段、写入条件与存储方式见 [日志与存储](./LOG.md)。

## 场次：一场的边界由自己划

真实比赛有起止时间：周六 00:00 UTC 开始，周日 24:00 结束。练习器没有这个钟——你什么时候想练就什么时候开，练多久都行。所以边界的意义从"时间"换成了"这一本账从哪儿开始数"。

- 日志页的比赛标签下多一行：**`本次 n` / `历史 m`**，加一个「开始新的一场」。
- **「开始新的一场」把这一本整体转入历史**：之后记的每一条都属于新的一场，旧的一本原样留着，随时翻回去看。**日志一条都不删**——这不是清空，是划线。
- **两个比赛各划各的线**：在 CQWW 上换场，WPX 那一本还在原来那一场。场次是账本自己的属性，不是机器的属性。
- **换场时 WPX 的序号回到 `001`**：新的一场从头数。设置里也能手动改回去，两种都行。
- **换场等于承认这次通联结束了**：如果正打到一半，正在填的那一行会清空（和切模式一样）。
- **正在写的那一场是默认视图**：页面上显示的就是"现在"。翻到「历史」是去看，回去点「本次」就回来；换标签或换场都会回到「本次」。
- **清空按钮只清屏幕上这一批**：在「本次」清本次，在「历史」清历史。跨三本的"清空全部"另有一个，同样点两次。

> 场次只是这本账上的一个分组，**它不筛选、不阻塞任何东西**：落账永远只看录入行填没填全（见 [日志与存储](./LOG.md) 的「写入条件」），与你在第几场无关。

## 重复通联：标出来，但通联照样做完

比赛里最常做的一件事：调到一个正在 CQ 的台，通完一半才想起"这个我好像通过"。

程序的处理和真实操作一样——**只标记，不打断**：

- 日志里多一列**重复**。判定是「**同一场 + 同一波段 + 同一呼号**」，已经记过就标`重复`。
- **判的是波段，不是频率**：14.0251 通一次、14.0317 再通一次，算重复；换到 7 MHz 就是新的一次。
- **不拦通联、不拦落账**：交换照做、`TU` 照发、那一行照记。真实情况下你也不会因为"好像通过了"就装作听不见——这是礼貌，也是操作纪律。
- **先通的那条不标**：标的是后一次。所以同一个台通了三次，有两条带 `重复`。
- 标记是**画页面时算出来的**（`ui/logDupes`），不写进存储：改了频率或呼号，标记自然跟着变，不会留下一个"当时算过"的死结论。

## 切模式时发生什么

模式选择器在机头左上角（`DX` / `CQWW` / `WPX`），**关台时也能改**——换的是"要说什么"，不是收发机。

- **换模式 = 放弃正在进行的这次通联**：措辞变了、交换的数字也变了，把一次通联跨越这个切换带下去，等于半句日常通联接半句比赛通联。所以会话重置、录入行清空，从头开始。**波段不动**：频段上的台还在原地，模式的新按键在报文文件读出来之前就已经在屏幕上了。
- 八个功能键换一份报文：桌面版是 `app-data/messages/` 下的 `DX.msg` / `CQWW.msg` / `WPX.msg` 三个文件，浏览器版用打包进去的对应默认（见 [快速报文与日志录入](./MESSAGES.md) 的「模式配置文件」）。
- 交换的数字与报文是两回事：改设置里的分区 / 序号**不会**重置会话，正在进行的通联照旧——那是"我发什么号"，不是"我在做什么模式"。

## 不做什么

比赛模式刻意停在这几件事之前：

- **不计分、不算系数、不做多波段统计、不模拟 10 分钟换频这类规则**。这个程序的产物是一本练习账，不是一份可提交的成绩单（日志不可导出，见 [日志与存储](./LOG.md)）。
- **不模拟"整个波段都在比赛"**：波段上的台仍按日常的节奏发 CQ、堆叠、互连，只是把措辞换成了比赛用语、交换里多了那个数字。所以调过去听到的不会是密不透风的比赛频段，而是稀疏的、像样的几个台。
- **不校验"这个台是不是真的在参加这场比赛"**：任何台问它分区 / 序号都会给。真实比赛里确实也有不参加的人，这里不做区分。
- **抄不到四位序号**：对方（虚拟台）的 WPX 序号由呼号派生，落在 `001`–`999` 之间，真实的 WPX 跑到后半程满是 `1xxx`。**但四位是合法的输入**——`1234` 照样能抄、能记，程序不会把它判成错误（练不到是练不到，错了是错了，两件事）。
- **不做跨波段的重复判断**：同一台在这个波段通过、那个波段还没通过，就是两次有效的通联。
- **旁边的两台仍在说日常通联那六行**（`sessionHamQso` 的脚本固定为 DX 形式），比赛模式下也一样。听到有人在比赛频段里慢慢聊，是真实的；另写一套比赛脚本不在这版范围内。
